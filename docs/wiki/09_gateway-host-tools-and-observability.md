# Gateway, Host Tools, and Observability

After a participant click has crossed the [connected mesh](05_connected-routing-and-reliable-delivery.md), the gateway becomes the boundary between protocol-owned research data and host-visible evidence. This page follows that boundary into the desktop GUI, headless capture tools, command timelines, and RTT qualification without treating a BLE write, a log line, or a quiet screen as proof that the underlying operation succeeded.

## The Gateway-to-PC Edge

The production-candidate [gateway](01_product-roles-and-firmware-lines.md) exposes one GATT service with three explicit boundaries: a notify characteristic for gateway-to-host records, a write/write-without-response characteristic for host-to-gateway packets, and a read-only characteristic containing the firmware `DEVICE_ID` ([app_gateway_ble.c:2574-2624](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L2574-L2624)). The desktop client checks all required UUIDs, reads that identity, subscribes before declaring itself connected, and splits a complete COBS-framed command into ordered write-without-response chunks sized for the characteristic ([ble_transport.py:145-185](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/ble_transport.py#L145-L185), [ble_transport.py:213-239](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/ble_transport.py#L213-L239)).

Outbound BLE is selective. Clicks, command results, surveys, diagnostics, and heartbeats are eligible; routing requests, hop acknowledgements, gateway ACKs/EACKs, event negotiation, and other mesh-control traffic stay off the normal host stream ([Gateway BLE Streaming.md:17-32](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20BLE%20Streaming.md#L17-L32)). Each record has a 40-byte header with packet identity, source and destination, gateway queue age, payload length, and payload CRC, so the host can reassemble one record across ATT notification chunks and reject corruption ([app_gateway_ble_stream.c:291-363](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble_stream.c#L291-L363), [protocol.py:867-911](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/protocol.py#L867-L911)).

The stream has bounded RAM and explicit pressure behavior. Clicks have the highest ordinary priority, results and surveys follow, then diagnostics and status; a higher-priority arrival may evict a lower-priority queued record, while non-truncatable records that still do not fit fail admission ([Gateway BLE Streaming.md:34-67](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20BLE%20Streaming.md#L34-L67), [app_gateway_ble_stream.c:366-544](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble_stream.c#L366-L544)). For records whose gateway ACK means semantic delivery, firmware reserves the complete host record before changing protocol state. A new click then commits its durable click journal before committing that reservation; only after semantic finalization can gateway delivery and its ACK become eligible ([app_mesh_report_delivery.inc:2679-2807](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_mesh_report_delivery.inc#L2679-L2807)).

Controller or notify-credit refusal leaves the selected chunk and stream record in custody and schedules capped exponential retry. It does not disconnect the PC after a fixed failure count. Pressure samples expose queue, custody, credit, retry, and drain depth, while warnings are sampled at power-of-two failure counts so a long outage remains visible without a tight log loop ([app_gateway_ble.c:2478-2490](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L2478-L2490), [app_gateway_ble.c:2826-3006](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L2826-L3006)). A successful callback advances one chunk; only completion of the full frame retires the stream head ([app_gateway_ble.c:2740-2801](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L2740-L2801)).

Gateway click delivery is at-least-once across gateway reset. The exact click payload and semantic packet identity remain in NVS until that full-frame callback; startup restores the record into a non-evictable stream item before a different click can take journal ownership. If reset lands after notification completion but before the NVS clear, the same click can be replayed, so the host must deduplicate exact identity and payload rather than claim end-to-end exactly-once delivery ([app_gateway_ble.c:706-737](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L706-L737), [app_gateway_ble.c:816-903](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L816-L903), [app_gateway_ble.c:2768-2795](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L2768-L2795)).

That distinction defines the boundary: BLE transports host commands and selected observations, while UWB still owns mesh RF delivery. Ordinary stream loss can hide diagnostic or status visibility without changing route or custody state, but semantically gated research records do not receive false gateway success merely because their RF frame arrived ([Gateway BLE Streaming.md:6-15](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20BLE%20Streaming.md#L6-L15)).

## Gateway GUI and Geometry Views

Run the desktop console from the repository root:

```sh
.venv/bin/python -m tools.gateway_gui
```

The GUI scans for IMEC devices, verifies the service, reads the gateway identity, and subscribes to notifications before enabling command controls. It clears identity on disconnect and refuses a contradictory gateway-local identity instead of deriving device identity from the BLE address ([README.md:20-44](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/README.md#L20-L44), [app.py:1170-1219](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/app.py#L1170-L1219)). The main workspace pairs a live packet table and transport activity log with inspectors for overview fields, aligned range samples, CIR windows, diagnostics, all TLVs, and raw bytes, while the diagnostics mixin adds mesh-command and geometry workflows.

The command panel deliberately exposes only the three validated gateway workflows:

| Workflow | What to inspect |
| --- | --- |
| **Anchor Survey Discovery** | The frozen discovery/pair profile, separately correlated route preflight, discovery reports, synchronized pair-round results, terminal timeline, and generated geometry. |
| **Here I Am** | The terminal route-refresh result and its typed lifecycle rather than the completed BLE write; as an immediate command, it does not preflight itself. |
| **Assign discovery slots** | The frozen assignment profile, separate route preflight, per-anchor claims, ACKed table entries, slot gaps, and terminal committed-anchor count. |

The host owns the ordinary command sequence. When the operator clicks Survey or Assign, the GUI freezes the target command and its complete versioned runtime profile, creates a Here-I-Am with a different session/sequence identity, and waits for that preflight's exact typed successful terminal before dispatching the target. A negative result, timeout, or disconnect clears the plan and leaves the target unsent. Here-I-Am and immediate recovery or liveness commands are exempt, preventing recursive preflight and recovery delay ([command_orchestration.py:12-90](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/command_orchestration.py#L12-L90), [command_orchestration.py:102-235](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/command_orchestration.py#L102-L235), [app.py:964-1090](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/app.py#L964-L1090)).

One profile encodes assignment expected count, budget, and equal randomized response spread; discovery start delay, slot duration/count, one to four rounds, report grace, and total budget; and pair reruns plus parallel-lane cap. The Python bounds mirror the firmware contract, so invalid operator input fails before transmission rather than being approximated silently ([operation_policy.py:10-45](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/operation_policy.py#L10-L45), [operation_policy.py:55-198](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/operation_policy.py#L55-L198), [app.py:814-864](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/app.py#L814-L864)). Those controls still use command-specific destinations and TLVs; there is no arbitrary command composer because firmware validation and single-command tracking do not promise arbitrary combinations ([README.md:106-135](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/README.md#L106-L135)).

A completed ATT write remains transport completion only: the UI reports that the command outcome is pending rather than upgrading the write to protocol success ([app.py:1150-1159](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/app.py#L1150-L1159)). Clicks have an additional host-session idempotence boundary. The GUI retains a bounded LRU cache across BLE reconnects for the lifetime of the process, suppresses only a click with the same packet identity, flags, and payload, and keeps a same-identity mutation visible as a conflict. Cache eviction and GUI restart mean this is not a persistent host acknowledgement or end-to-end exactly-once guarantee ([delivery_dedup.py:1-8](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/delivery_dedup.py#L1-L8), [delivery_dedup.py:71-154](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/delivery_dedup.py#L71-L154), [app.py:1254-1283](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/app.py#L1254-L1283)).

The geometry path continues the [anchor self-setup story](07_anchor-self-setup-survey-and-geometry.md). `Anchor Geometry` consumes successful survey-pair distances; failed pairs become visibility evidence only after terminal telemetry proves the scheduled opportunities were observed, and the selected solver does not silently fall back after failure. `Click Location` groups ranges by protocol session, event sequence, and clicker identity against the current geometry generation, leaving stale, duplicate, unknown-anchor, invalid, or collinear inputs unsolved ([README.md:174-188](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/README.md#L174-L188)).

For headless checks, use `.venv/bin/python -m tools.gateway_gui.ble_smoke [BLE_ADDRESS]` to require identity-read and subscription success, or use `tools/mesh_ble_route_monitor.py` for a bounded, scriptable stream capture. The smoke check proves the GATT edge is usable; it does not prove that a later UWB command or mesh delivery succeeds ([README.md:61-95](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/README.md#L61-L95)).

## Command and Lifecycle Telemetry

Typed `MSG_GATEWAY_COMMAND_EVENT` records turn assignment, survey, and route refresh into timelines without replacing their existing command-result or survey-result packets. Every fixed 78-byte event carries command kind and stage, status and reason, host correlation ID, original host session and sequence, gateway operation sequence, monotonically increasing event sequence, involved anchors or pair, previous hop, counts, hop count, and slot ([Gateway Command Observability.md:70-108](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20Command%20Observability.md#L70-L108)).

Correlate one firmware command by `(command_kind, correlation_id, host_session_id, host_seq)`, use `gateway_sequence` to distinguish its assignment epoch or survey ID, and sort by `event_seq`. Replayed snapshots keep their original event sequence and replace the same timeline position, so reconnect does not invent another operation ([Gateway Command Observability.md:143-159](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20Command%20Observability.md#L143-L159)). One GUI operation can intentionally contain two such timelines: the separately correlated Here-I-Am preflight must reach its successful terminal before the frozen target is sent, and neither timeline may borrow the other's terminal identity ([command_orchestration.py:70-90](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/command_orchestration.py#L70-L90), [command_orchestration.py:134-176](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/gateway_gui/command_orchestration.py#L134-L176)).

The evidence levels matter:

| Observation | What it proves | What it does not prove |
| --- | --- | --- |
| BLE write completion | The host submitted every ATT chunk. | Gateway command acceptance, RF dispatch, or terminal success. |
| Valid stream header and payload CRC | The selected host record was reassembled intact. | That every RF or low-priority observability event appeared on BLE. |
| Accepted, queued, retry, or pair-stage event | The gateway reached that correlated lifecycle stage. | A successful terminal outcome. |
| Terminal event or matching terminal `COMMAND_RESULT` | The gateway declared the correlated operation terminal with explicit status and reason. | Remote attestation of the target or proof outside the stated protocol boundary. |
| Gateway ACK for a semantically gated record | The gateway protocol owner accepted the record after reserving or committing required downstream custody. | That BLE completed, an operator exported it, or the host will never see an exact reset replay. |

Terminal command events receive click-level priority and are retained until their complete stream record is acknowledged by the BLE callback. Disconnect, CCC-off, exhausted notification credit, transient submit failure, and queue pressure leave records pending for replay; sequence gaps count as irreversible loss only when `lost_event_count` also advances ([Gateway Command Observability.md:31-61](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20Command%20Observability.md#L31-L61)). The implementation retains a bounded terminal backlog, preserves snapshots after transient enqueue refusal, and marks replayed snapshots explicitly ([app_gateway_command_observability.c:287-367](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_command_observability.c#L287-L367), [app_gateway_command_observability.c:369-445](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_command_observability.c#L369-L445)). Transient notification refusal keeps that custody and schedules capped exponential retry; it no longer turns the eighth failure into a forced disconnect ([app_gateway_ble.c:2826-3006](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L2826-L3006)).

Backpressure may coalesce non-terminal progress to the latest safe snapshot, but it does not change radio deadlines or survey decisions. Assignment publication retains its exact table batch and advances one mapping only after the send callback. Survey telemetry is admitted at a lane boundary; if it lacks custody capacity, that lane remains pending while unrelated lanes retain their exact radio and cleanup state ([Gateway Command Observability.md:53-68](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20Command%20Observability.md#L53-L68), [Gateway Command Observability.md:192-200](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20Command%20Observability.md#L192-L200)). Survey discovery completes its configured continuous randomized-round horizon before `NO_ANCHORS`; an overall host limit expires as `TIMEOUT` rather than shortening that horizon ([Gateway Command Observability.md:164-182](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20Command%20Observability.md#L164-L182)). The GUI must decide success from the authoritative terminal record, never from silence, a transport write, or the absence of an error.

## RTT, Route Monitoring, and Durable Captures

Use each host evidence path for the question it can answer:

| Tool or artifact | Best use | Evidence limit |
| --- | --- | --- |
| Gateway GUI | Interactive packet, command, CIR, survey, and geometry inspection. | Selective host-delivery view, not a complete RF trace. |
| BLE route monitor | Headless packet sequencing, hop/retry inspection, gaps, and repeatable captures. | Observes only records the gateway stream emitted and the host received. |
| Append-only JSONL | Machine-readable host arrival records for later correlation. | A missing record can mean filtering, pressure, disconnect, decode failure, or upstream absence. |
| Ordinary RTT transcript | Target-local boot, route, ACK, stack, and failure markers. | Marker presence is meaningful only under a validator that defines required milestones and rejects fatal or repeated-boot traces. |
| Schema-3 typed RTT capture | Exact-artifact qualification for [verified deployment](11_verified-deployment-and-qualification.md). | Strong local provenance, not cryptographic remote probe attestation. |

The BLE route monitor derives a sequence class from packet IDs, mesh event counters, event sequence, requested sequence, or packet sequence. It tracks the high-water mark independently for each `(source_id, sequence_class)`, reports missing ranges, resets, and out-of-order arrivals, and deliberately does not move the high-water mark backward for a late record ([mesh_ble_route_monitor.py:329-397](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/mesh_ble_route_monitor.py#L329-L397)). That makes a gap actionable without confusing interleaved node-local streams. A temporary pause is not itself a gap: notification refusal retains the current record behind capped exponential retry, while pressure diagnostics expose zero credit, retry depth, and queue depth ([app_gateway_ble.c:2826-3006](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/app/src/app_gateway_ble.c#L2826-L3006)).

For a durable headless capture, pass `--jsonl-file PATH`; the monitor opens it with append semantics, writes each JSON object completely, and optionally calls `fsync` for every record with `--jsonl-fsync`. Capture write failures increment `capture_errors`, appear in the final summary, and make the process exit nonzero ([mesh_ble_route_monitor.py:436-472](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/mesh_ble_route_monitor.py#L436-L472), [mesh_ble_route_monitor.py:623-794](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/mesh_ble_route_monitor.py#L623-L794)). `--jsonl-fsync` improves survival across host power loss at the cost of one synchronous flush per packet.

Formal RTT qualification uses the repository capture tool, which runs `pyocd rtt -t nrf52833 -M pre-reset -u <probe> --up-channel-id 0` under a TTY-providing `script` wrapper and bounded timeout. It rejects an empty transcript, then binds exact ELF and HEX hashes, preset, target build identity, probe ID, transcript hash, fixed command, and UTC window into the manifest before verifying it ([capture_stack_evidence.py:61-128](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/scripts/capture_stack_evidence.py#L61-L128)). This is why an ad hoc redirected RTT log and a qualification capture are different artifacts.

Stack attribution has two complementary gates. Static evidence parses every linked application object's compiler stack-usage record and call graph, rejects missing or stale artifacts, and attributes reachable functions only through policy-declared thread roots. Runtime watermarks then require threads that still exist at workload sampling time. The startup main thread has already returned and integrated-controller HCI TX is a synchronous call-stack setting, so both remain covered by exact configuration and compiler evidence instead of being misreported as missing live RTT threads ([verify_stack_evidence.py:227-243](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/scripts/verify_stack_evidence.py#L227-L243), [verify_stack_evidence.py:880-957](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/scripts/verify_stack_evidence.py#L880-L957), [verify_stack_evidence.py:963-1015](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/scripts/verify_stack_evidence.py#L963-L1015)).

The typed transcript still has to prove real workload ownership. The verifier requires correlated `RUN_BEGIN`, `SAMPLE_BEGIN`, stack rows, sample completion, and `RUN_END` records; it matches source, destination, session, sequence, message type, workload owner, and run identity while recording queue, custody, credit, retry, and drain state. Unknown thread owners, wrong generated stack sizes, insufficient free space, unmatched or overlapping samples, unterminated runs, marker-only logs, and missing required successful workloads all fail closed ([verify_stack_evidence.py:1067-1086](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/scripts/verify_stack_evidence.py#L1067-L1086), [verify_stack_evidence.py:1089-1222](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/scripts/verify_stack_evidence.py#L1089-L1222)).

When correlating host and target evidence, prefer protocol identity over wall-clock proximity: use source/destination, session, packet sequence, event sequence, and command correlation tuple. Host elapsed and Unix arrival times explain when the PC observed a record, while target uptime and typed run identity explain where firmware was; neither clock alone proves that they describe the same operation ([mesh_ble_route_monitor.py:436-460](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/tools/mesh_ble_route_monitor.py#L436-L460), [Gateway Command Observability.md:143-159](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/Documentation/Gateway%20Command%20Observability.md#L143-L159), [verify_stack_evidence.py:1111-1144](https://github.com/Jubliano-sama/IMEC2/blob/fda75299b34b5ec207fedd387f48e3d2652b5aea/firmware/scripts/verify_stack_evidence.py#L1111-L1144)).
