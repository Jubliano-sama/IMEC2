# Demo recovery implementation — 2026-09-06

This follows the read-only [recovery/scale/power audit](recovery-scale-power-audit-2026-09-05/README.md). Subsequent user direction prioritized failures likely to interrupt a demo and authorized firmware changes and four-board role changes. The historical audit remains evidence of the original source, not a statement that every finding is still open.

## Implemented

- Enumeration retains the 125 ms round and 75 ms TX window, but uses twenty source rounds. Full node identity and round decorrelate retries even with a repeated random value or identical temporary hash slots. Rounds 1–11 reduce competing source attempts; round zero, the final eight source rounds, and forwarding rounds remain unconditional. Source plus the deepest forwarding tail takes 4,250 ms inside the unchanged 4,500 ms HIA depth block. The legacy eight-depth lane and shared survey result lane grow from 19 to 27 seconds; GUI estimates and admission-budget tests use the same values.
- Ordinary CRC/PHY errors in the gateway compact receiver rearm through the existing error classifier instead of resetting the DW3000 after every collision. Unknown/hard errors still invoke full recovery.
- Survey scheduling is bounded for every aggregate size, with fair deferral when nine bundles cannot all fit the same TX span. Bundle admission preflights the whole immutable aggregate. Raw survey wire version 2 binds ACKs to the batch and SHA-256 of the exact canonical bundle.
- Survey START consumes a generation from the existing pre-reserved durable control-ID allocator. It performs no additional NVS write per survey. Fresh accepted enumeration authority retires an abandoned anchor survey; physical RF ownership remains with its worker until abort cleanup completes.
- Gateway graph, plan, signals, batch and terminal publications retain bounded ownership through BLE admission, and survey packets require host receipts. BLE receipts have a reserved ingress slot and bypass commands waiting for result credit. GUI state reconciles through its existing GET_STATUS owner. A failed fragmented ATT write disconnects before another frame can append to its abandoned prefix.
- C5 banks expire old custody through the producer's failed-completion path, retry busy cleanup without reporting success, and reserve one of four entries for a local report.
- Passive gateway-command reverse hints preserve measured weak-link and failure evidence and receive the listener's actual RSL. Fresh advertisements retain recovery authority; hop-first route cost is unchanged. Duplicate state save/restore loops were removed.
- The supported command-set anchor scan interval is at most 435 ms, accounting for rearm, RX and complete-frame completion. Two-scan uplink wake coverage uses the receiver ceiling, independent of the sender's cadence. Ordinary 500 ms click/HIA trains remain unchanged. An unknown production discovery depth is conservatively reported as the maximum supported depth.
- Battery sampling attempts divider cleanup even after partial enable failure, and an unproven off state triggers restart. A held clicker button uses release interrupts instead of indefinite 5 ms polling. Known terminal radio faults and failed scan scheduling request a one-second cold restart from an independent kernel timer; the hardware watchdog remains the fallback.

## Native and host evidence

Before first flash: 206/206 native tests, 170/170 mesh-integration tests, 162/162 hardware-model tests, and 292/292 GUI unittest tests passed. Label suites ran sequentially because some Zephyr seam tests share build directories. The final full native run after the live BLE-worker correction also passed all 206 tests (final-native.log).

The direct-star compact RF model completes all thirty identities and exact ACKs in 1,024 random seeds at modeled 4 ms ACK turnaround and 0.5 ms rearm. It also completes 1,024 thirty-anchor populations that deliberately share one actual temporary hash slot, start with coincident transmissions, and receive the same repeated random draw. It models complete frame containment, overlapping-frame collisions, ACK airtime and nonzero turnaround. It starts after HIA activation and does not prove dense low-duty activation, physical hidden hops or a thirty-board deployment. Fifty-node contention still has incomplete runs; fifty remains an encoding/state capacity ceiling.

The production builds fit the nRF52833: gateway 125,760 bytes RAM / 472,640 bytes flash; anchor 124,800 / 455,584; clicker 97,680 / 429,904. Exact images and flash logs are recorded with the bench evidence.

Live GDB proved an empty BLE RX queue repeatedly reserving and releasing a command-result token, whose release rescheduled the same cooperative worker and starved radio work. The corrected worker exits before reserving on an empty queue; its regression models the scheduling feedback and fails under mutation that removes the guard. Both required label suites passed again before reflashing the gateway. The corrected DDD run passed: all three anchors enumerated, all three pairs returned five successful samples, and the GUI received terminal completion with no partial reasons. A gateway-only reboot followed by the next complete survey also passed. A separate automated case read all three active anchor owners immediately before resetting only the gateway; the next enumeration and survey passed in 69.136 seconds with a new generation and all five samples for every pair, before the prior 180-second lease could expire. Evidence is in ddd-fixed-survey.log, ddd-reboot-survey.log and live-owner-restart/ (including owners-before-reset.json). Current logs are in logs/recovery_implementation_20260906/. F1F1D also passed: both children were observed at hop 2 through the same direct parent, then three separate one-pair batches completed with five samples each and no partial reasons (f1f1d-survey.log). The first F2F1D run enumerated depths 1/2/3 and completed its two adjacent-layer neighbor pairs with five samples each; the harness incorrectly expected three pairs and marked that run false. The captured graph is 0–1–2. Repeating without resetting the anchors and with the correct two-pair expectation passed in 97.336 seconds (f2f1d-repeat-survey.log).

Click qualification used the existing two-anchor bench option on all four participants, with RTT gesture injection enabled only on the clicker. Four boards cannot simultaneously provide a separate gateway, clicker and the production quorum of three anchors. Ten F1D clicks produced twenty unique reports, each with six samples and zero range error, and every report received its exact host receipt (f1d-clicks/). Across the five normal-click cases, all 24 clicks produced both expected anchor reports: 48 reports, each with six successful samples and an exact host receipt (click-results.json).

## Deferred under the demo-first scope

Replacing or mass-erasing a gateway can rewind its route epoch against surviving anchors. Ordinary self-reboot uses the durable incarnation and does not have that rewind. This maintenance scenario still needs an explicit authority/rebase rule; corrupt NVS is not silently erased.

Forced-hop filtering remains decode-layer testing. Sleeping hidden-parent route solicitation, dense HIA activation, physical asymmetric links, full arbitrary thirty-node branching, and removal of reachable legacy Channel-9 paths remain unqualified. No claim is made that every function has exhaustive recovery proof.

Raw survey wire version 2 requires updating the gateway and participating anchors together; mixed old/new survey firmware is not supported by this change.

No current measurement was performed. Retained clicker idle, LED feedback, BLE politeness, diagnostics and anchor PHY sleep/rearm policy remain unchanged apart from the divider/held-button recovery fixes. Deeper power tuning requires measurement; shortening essential RF coverage was not used as a power optimization.
